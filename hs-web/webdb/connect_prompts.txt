[프롬프트 3] 회원가입 · 로그인 · 마이페이지

이어서 회원 기능을 Supabase 로 바꿔줘. 연결은 앞에서 만든 db.js 의 db 를 그대로 써.

[표 구조] shop_profiles ( id, email, name, phone, grade, points, role, created_at )
- 가입하면 DB 가 이 표에 한 줄을 자동으로 만든다.
- grade 는 WELCOME · SILVER · GOLD · VIP 네 가지, 가입하면 WELCOME 이다.
- points 는 가입하면 3000 이다.

할 일:
① 회원가입은 db.auth.signUp 으로 바꾸고, 이름과 연락처는 options.data 의 name · phone 으로 함께 보내줘.
② 로그인은 db.auth.signInWithPassword, 로그아웃은 db.auth.signOut 으로 바꿔줘.
③ 모든 페이지가 열릴 때 db.auth.getSession 으로 로그인 상태를 확인해줘. 로그인 중이면 메뉴에 「이름 님 · 로그아웃」, 아니면 「로그인 · 회원가입」 을 보여줘.
④ 마이페이지는 shop_profiles 에서 내 한 줄을 읽어 이름 · 이메일 · 등급 · 포인트를 보여주고, 이름과 연락처는 고쳐서 저장할 수 있게 해줘.
⑤ 회원 정보와 비밀번호를 브라우저(localStorage)에 저장하던 코드는 모두 지워줘.

조건:
- grade · points · role 은 화면에서 고치지 마. DB 가 막아 두어서 오류가 나. 읽기만 해.
- 내 쇼핑몰의 등급 이름이 다르면 화면에 보여 줄 때만 바꿔줘. [예: WELCOME → BRONZE]
- 비밀번호는 6자 이상이라고 가입 화면에 안내해줘.
- 이미 가입한 이메일, 틀린 비밀번호 같은 오류는 한글 안내문으로 보여줘.
- 로그인하지 않고 마이페이지를 열면 로그인 화면으로 보내줘.
- 디자인은 그대로 둬.

출력 형식:
① 고친 파일 전체 (파일 이름을 먼저 적고)
② 내가 직접 해 볼 확인 순서 5단계 (가입 → 표 확인 → 로그아웃 → 로그인 → 마이페이지)

마지막으로 localStorage 에 회원 정보를 저장하는 코드가 남아 있지 않은지 스스로 검증하고 결과를 알려줘.

[프롬프트 5] 결제하면 주문이 표에 남게 하기

이어서 체험 결제를 누르면 주문이 Supabase 표에 저장되게 바꿔줘.

[표 구조]
- shop_orders ( id 자동 번호, user_id, total, status, created_at )
- shop_order_items ( order_id, product_id, qty, unit_price ) — 기본키가 (order_id, product_id) 라서 한 주문에 같은 상품은 한 줄만 들어가.

할 일:
① 결제 버튼을 누르면 먼저 로그인했는지 확인하고, 안 했으면 로그인 화면으로 보내줘.
② shop_orders 에 { total } 한 줄을 넣고, .select().single() 로 방금 만든 주문의 id 를 받아줘.
③ 받은 id 로 shop_order_items 에 장바구니 상품을 { order_id, product_id, qty, unit_price } 로 한꺼번에 넣어줘.
④ 두 번 모두 성공하면 장바구니를 비우고 주문 완료 화면에 주문 번호와 합계를 보여줘.
⑤ 마이페이지에 내 주문 내역을 최신순으로 보여줘. 주문 번호 · 날짜 · 합계 · 상태와 함께 담긴 상품 이름과 수량도 보여줘.

조건:
- user_id 와 status 는 보내지 마. DB 가 로그인한 사람과 「결제완료」 를 자동으로 넣어.
- total 은 수량 × 단가를 모두 더한 값으로 계산해줘.
- 장바구니에 같은 상품이 두 번 담겨 있으면 수량을 합쳐 한 줄로 보내줘.
- 포인트 적립과 사용은 표에 저장하지 마. points 는 관리자만 바꿀 수 있어. 화면에 「적립 예정 nP」 로만 보여줘.
- 재고(stock)도 줄이지 마.
- 저장에 실패하면 오류 메시지를 화면에 보여주고 장바구니는 그대로 둬.
- 실제 결제는 하지 않아. 카드 번호 같은 값은 받지도 저장하지도 마.

출력 형식:
① 고친 파일 전체 (파일 이름을 먼저 적고)
② 내가 직접 해 볼 확인 순서 4단계 (담기 → 결제 → Table Editor 의 두 표 확인 → 마이페이지)

마지막으로 주문 한 건에 넣은 주문 상세의 합이 total 과 같은지 스스로 검증하고 결과를 알려줘.

[프롬프트 6] 회원 · 주문 관리 페이지 만들기

※ 먼저 쇼핑몰에서 내 이메일로 가입한 뒤, SQL Editor 에서 아래 한 줄을 실행해 내 계정을 관리자로 만듭니다.
UPDATE public.shop_profiles SET role = 'admin' WHERE email = '[내 이메일]';

이어서 admin.html 을 새로 만들어줘. 내 쇼핑몰과 같은 db.js 를 불러와 써.

할 일:

② 회원 목록: shop_profiles 전체를 표로 보여줘 (이름 · 이메일 · 연락처 · 등급 · 포인트 · 역할 · 가입일). 이름 검색과 등급 필터를 넣어줘.
③ 회원의 등급 · 포인트 · 역할을 고쳐 저장하면 shop_admin_update_member 함수를 불러줘. 넘기는 값의 이름은 p_user_id, p_grade, p_points, p_role 이야.
④ 주문 목록: shop_orders 를 최신순으로 보여주고, 상태를 결제완료 · 배송중 · 배송완료 · 취소 가운데에서 바꿀 수 있게 해줘.
⑤ 맨 위에 요약 숫자 세 가지를 보여줘: 회원 수, 주문 건수, 주문 합계.

조건:
- 회원 표를 update 로 직접 고치지 마. 등급 · 포인트 · 역할은 ③의 함수로만 바꿀 수 있어.
- 등급은 WELCOME · SILVER · GOLD · VIP, 역할은 member · admin 만 고를 수 있게 선택 상자로 만들어줘.
- 포인트에는 0 이상의 정수만 들어가게 해줘.
- 디자인은 내 쇼핑몰과 같은 색 · 글꼴로 맞추고, 표가 화면보다 넓으면 표 안에서만 좌우로 넘기게 해줘.
- 쇼핑몰 메뉴에는 관리자에게만 「관리」 링크가 보이게 해줘.

출력 형식:
① admin.html 전체
② 메뉴에 「관리」 링크를 넣느라 고친 파일 전체
③ 내가 직접 해 볼 확인 순서 4단계 (관리자로 열기 → 등급 고치기 → 표 확인 → 일반 회원으로는 돌려보내지는지)

④ 회원 정보나 비밀번호를 브라우저(localStorage)에 저장하는 코드가 남아 있지 않은가
⑤ grade · points · role · stock 을 일반 회원 화면에서 고치려는 코드가 없는가
⑥ 그림과 파일 경로가 모두 상대경로이고, 파일 이름의 대소문자가 실제 파일과 같은가
⑦ 첫 화면 파일 이름이 index.html 인가
